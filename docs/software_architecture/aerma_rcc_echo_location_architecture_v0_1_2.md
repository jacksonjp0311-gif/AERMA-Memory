Define the software architecture for a repo-local RCC Echo Location layer inside AERMA-Memory.

The purpose is to make the repository self-locating for humans and AI agents:

    agent sees repo URL
    -> reads root beacon
    -> understands project identity
    -> follows route map

    -> patches smallest safe surface
    -> validates tests, suite, guard, and RCC

8. RCC Folder Contract

The `rcc/` folder is a repo-local module with five responsibilities:

1. echo: agent entry, route map, protocol, handoff.
2. checks: drift checks and rule files.
3. reports: generated RCC health/drift outputs.
4. templates: reusable context templates.
5. schemas: optional validation schemas.

The `rcc/` folder must not contain AERMA runtime code. It governs context and navigation only.

9. Agent Route Map Contract

The route map must be machine-readable JSON.

Minimum fields:

    repo
    entry_order
    task_routes
    required_validation
    non_claim_locks
    update_obligations

Task routes should include:

    read_only_review
    documentation_change
    rcc_change
    runtime_change
    scoring_change
    benchmark_task_change
    evidence_change
    test_change
    release_or_public_claim_change

A route is valid only if it tells an agent:

    what to read
    what may be edited
    what validations to run
    what context to update
